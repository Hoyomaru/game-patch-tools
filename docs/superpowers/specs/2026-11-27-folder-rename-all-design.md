# フォルダ名をそろえる：ブックマークにない作品も対象にする 設計

2026-11-27（`2026-11-27-folder-rename-design.md` の続き）

## 目的と理由

1.8.0 の「フォルダ名をそろえる」は、ブックマーク（とそのバックアップ）の作品名と完全に一致したフォルダだけを対象にした。ところが、ユーザーの手元を件数だけ数えると次のとおりで、**1件も対象にならない**ことがわかった。

- 手元の候補 516 件のうち、名前に RJ番号がないもの 469 件（見る深さ 3 なので、作品でないフォルダも混ざっている）
- ブックマーク・バックアップ 499 作品のうち「持っている」は 15 件で、どれも元からフォルダ名に RJ番号があるもの。RJ番号なしのフォルダで作品名が一致したものは 0 件（フォルダ名が適当なため）
- フォルダの中から RJ番号が1つだけ見つかる：30 件（2つ以上で決められない：8 件）
- フォルダの中から作品名が読める：133 件（Unity 73・ツクールMV/MZ 51・package.json 9）。ただしブックマークの作品名とは 0 件一致
- 作品名が読めず exe だけある：59 件

ブックマークに入れたことのない作品のフォルダも RJ番号入りにしておけば、あとでその作品をブックマークしたときや更新を確かめるときに、確実に「RJ番号が一致」になる。**目的は 1.8.0 と同じく判定を確実にすること**。

## ねらい・やらないこと・失敗とみなすこと

ねらい
- RJ番号のない手元の作品（フォルダ・アーカイブ）に、RJ番号の候補を付けて一覧に出す
- 候補の出どころは強い順に：①中に書いてある RJ番号 ②DLsite の検索 ③自分で入れる
- 確かな候補だけ最初からチェック。ほかは自分で選んでから変える
- 名前の変え方・記録・戻し方・`owned-links.json` の書き換えは 1.8.0 のものをそのまま使う

やらないこと
- 名前を変えずに対応だけ覚えておく仕組み（名前に入れた方が、フォルダを動かしても外れない）
- AS Patch Finder（ブラウザ）での検索
- 置き場所を変えること、外部ランチャーとの連携

失敗とみなすこと（動いていても）
- 違う作品の RJ番号が、ユーザーが確かめないまま付く（検索の上位が違う作品だった、など）
- サークルでまとめたフォルダや、ゲームの中のフォルダの名前を変えてしまう
- DLsite に、検索する言葉以外（パス・ほかのフォルダの情報など）を送る
- 数百件の検索で画面が固まり、止められない・進み具合がわからない

## 前提・制約

- Windows / PowerShell 5.1、追加のインストールなし
- ネットに送るのは、作品名を取るときの RJ番号と、**検索する言葉（ゲームの中の作品名か、フォルダ名を整えたもの）だけ**。README の「送るのは RJ番号だけ」を書き直し、送る前に件数を聞く（ユーザーは送ってよいと答え済み）
- 作品名は画面以外（ログ・コンソール・コミット）に出さない。テストの名前は架空のもの
- DLsite への問い合わせは 1 件ごとに間を空ける（今の `Get-DLsiteTitles` と同じく 800 ミリ秒ほど）
- 個人のデータ（検索結果の保存）は `.gitignore` に入れる

## 作り方の候補

| 案 | 中身 | 良いところ | 悪いところ |
|---|---|---|---|
| **1. 今の一覧に足す（採用）** | ブックマークに当たらない作品も一覧に出し、候補の RJ番号を選んで変える | 名前の変え方・記録・戻し方をそのまま使える。1つの画面で済む | 一覧が大きくなる |
| 2. 「RJ番号を調べる」を別の段階にする | フォルダと RJ番号の対応をファイルに覚え、名前はあとで変える | 名前を変えなくても使える | 覚えるものが増え、フォルダを動かすと外れる |

外した案：AS Patch Finder で検索する（手元のフォルダを読めない）。

## 決めたこと

### 作品とみなすもの
- アーカイブ（今と同じ zip / rar / 7z / lzh）
- フォルダは、直下にゲームの印があるものだけ：`.exe` ファイル、`*_Data` フォルダ、`www` フォルダ、`data\System.json`、`Game.ini`、`package.json`
- 印のあるフォルダの中のフォルダは作品とみなさない（ゲームの中のフォルダ）
- 印のないフォルダの子のうち、印のあるフォルダが1つだけなら（`作品名\Game\Game.exe` や二重展開の `作品\作品\…`）、外側を作品とみなして外側の名前を変える（設計者の判断：内側は `Game` のような汎用の名前が多く、1.8.0 も二重展開は外側を変えている）
- 「印がある」の条件は、新しく足す行（ブックマークに当たらない作品）だけにかける。ブックマークに当たった行は 1.8.0 のまま（設計者の判断：前より対象が減らないように）
- 1.8.0 と同じく、名前に RJ番号があるもの・② に登録したゲームフォルダとその親は対象にしない
- 「たぶん持っている」の候補になっている手元の作品は、新しく足す行にも入れない。右クリックで確かめてもらう（設計者の判断：1.8.0 の方針と同じ。別の番号を付けるとブックマーク側の判定とぶつかる）。「持っていない」の行の「いちばん近い」候補は、当たったわけではないので、ふつうに検索に回す
- アーカイブの中身は読まない。アーカイブはファイル名だけで検索する（設計者の判断：追加なしで読めるのは zip だけで、件数も 3 件と少ない）

### 手がかり
1. **中に書いてある RJ番号**：中のファイル名と、小さなテキストファイル（200KB 未満の `.txt .url .html .htm .md .ini .json .nfo`、1 作品につき 50 個まで）の中身から探す。1つだけならそれを使う。2つ以上なら検索に回し、見つかった番号も候補に並べる
2. **ブックマーク・バックアップとの一致**：1.8.0 と同じ（RJ番号・作品名の完全一致・確かめた対応）
3. **DLsite の検索**：1 と 2 で決まらなかったものだけ。検索する言葉は、ゲームの中の作品名（ツクールMV/MZ の `System.json` の `gameTitle`、ツクールVX/XP の `Game.ini` の `Title`、`package.json` の `window.title` か `name`、Unity の `*_Data\app.info` の2行目）。読めなければフォルダ名から版・括弧・記号を除いたもの。R18（maniax）と全年齢（home）の両方の売り場で検索し、上位5件ずつを候補にする
4. **自分で入れる**：一覧の行に RJ番号か DLsite の URL を貼れる

### 最初からチェックを付けるもの
- 中に書いてある RJ番号が1つだけ
- ブックマーク・バックアップと一致（1.8.0 と同じ）
- 検索の候補のうち、正規化した作品名（`Normalize-Title`）が検索した言葉と完全に一致するものが、R18 と全年齢の2つの売り場を合わせて1つだけ。**ただし検索した言葉がゲームの中の作品名のときだけ**。フォルダ名から作った言葉で一致しても、最初はチェックなし（設計者の判断：フォルダ名は適当なので、「RPG」のような短い言葉が別の作品と一致しうる）
- それ以外は、候補を選ぶか自分で入れて、チェックを付けてから変える

### 一覧
- 1.8.0 の一覧に「RJ番号（選べる）」「手がかり」の欄を足す。手がかりは「中に書いてある」「ブックマークと一致」「DLsite で検索（一致）」「DLsite で検索（候補）」「自分で入れた」
- RJ番号を選ぶ・入れると、その番号の正式な作品名で新しい名前を作り直す
- 候補の作品をダブルクリックで DLsite のページを開いて確かめられる
- 見つからなかった行も一覧に残し、自分で入れられるようにする

### 検索の進め方
- 送る前に「N 件を DLsite で検索します（送るのは検索する言葉だけ）」と聞く
- 進み具合（何件中何件）を出し、途中で止められる。止めても、そこまでの結果は使える
- 検索の結果は保存しておき、次からは調べていないもの（と、前に何も見つからなかったもので言葉が変わったもの）だけ検索する
- 作っている間に、検索結果ページの形や全年齢の売り場の URL を確かめるため、一般的な言葉で数回だけ DLsite に問い合わせてよい（ユーザーのフォルダ名や作品名は使わない）。テスト用の HTML の例は、作品名を架空に置き換えて保存する

## 作る人に任せること

- 検索の結果の保存先と形（例：`dlsite-search-cache.json`、`.gitignore` に追加）
- 画面を固めずに検索する方法（Application.DoEvents で回す、別のスレッド、など）と「止める」の作り
- DLsite の検索結果ページ（`/maniax/fsr/ajax/=/language/jp/keyword/<言葉>/per_page/5/` が JSON の中に HTML を返す）から RJ番号と作品名を読む方法。売り場ごとの URL
- フォルダ名から検索する言葉を作るときの細かい規則
- 一覧の RJ番号の欄の作り（コンボボックス＋手入力など）
- テスト：作品とみなす判定、中の RJ番号探し、ゲームの中の作品名の読み取り、検索結果の読み取り（保存した HTML の例を使う。作品名は架空に置き換える）、最初からチェックを付ける判定

# フォルダ名をそろえる（所持チェック）設計

2026-11-27

## 目的と理由

手元のゲームフォルダの名前は、つけた時のままでバラバラ（意味のあるメモも入っていない）。そのため、所持チェックは作品名の似かたで判定するしかなく、「たぶん持っている」や見落としが出る。

フォルダ名に RJ番号を入れておけば、判定はいつも「RJ番号が一致」になり、持っている作品の更新確認（AS Patch Finder に渡す）も確実になる。**目的は判定を確実にすること**で、見た目は二の次（あとで外部ランチャーに取り込むなら、フォルダ名はほとんど見ない）。

## ねらい・やらないこと・失敗とみなすこと

ねらい
- どの作品かがはっきりしているフォルダの名前を `RJ番号 正式な作品名 v版` にそろえる
- 変える前に「今の名前 → 新しい名前」を一覧で見て、チェックしたものだけ変える
- 変えたあとも、確かめた対応（`owned-links.json`）がそのまま効く
- 元に戻せる

やらないこと
- 「たぶん持っている」「持っていない」のフォルダの名前は変えない（先に右クリックで確かめてもらう）
- すでにフォルダ名に RJ番号が入っているフォルダは変えない（判定にはもう十分）
- サークル別に移すなど、置き場所を変えること（別の話）
- 外部ランチャーとの連携（別の話）

失敗とみなすこと（動いていても）
- 違う作品の RJ番号を付けてしまう（判定がかえって狂う）
- 名前を変えたせいで、確かめた対応や版の読み取りが外れる
- ゲームの中のフォルダや、ゲームフォルダそのもの（② に登録した場所）の名前を変えてしまう
- 一部だけ変わって、どこまで変わったかわからなくなる

## 前提・制約

- Windows / PowerShell 5.1、追加のインストールなし（今の所持チェックと同じ）
- ネットにアクセスするのは作品名を取るときだけで、送るのは RJ番号だけ（README の約束と同じ）。今の `Get-DLsiteTitles` を使う
- 作品名はユーザーに見せる画面以外（ログ・チャット・コミット）に出さない
- 個人のデータ（変えた記録など）は `.gitignore` に入れ、リポジトリに入れない

## 作り方の候補

| 案 | 中身 | 良いところ | 悪いところ |
|---|---|---|---|
| **1. 所持チェックの画面にボタンを足す（採用）** | 「フォルダ名をそろえる…」で一覧を出し、チェックしたものを変える | チェックの結果・`owned-links.json`・バックアップの流れをそのまま使える。「たぶん」を確かめてすぐ変えられる | 画面を作る手間がある |
| 2. 別のスクリプト | 照らし合わせをやり直して、名前を変える | 作るのが少し楽 | 一覧で確かめにくい、照らし合わせをやり直す |

外した案：名前を変えるだけの別ツール（判定の結果を使えず目的に合わない）。

名前の形は「今の名前の前に RJ番号を付けるだけ」と「正式な作品名に置き換える」を比べ、**正式な作品名に置き換える**に決めた（今の名前に残したいメモがないため）。

## 決めたこと

### 対象
- `Get-OwnedWorks` と同じ範囲の「持っている」作品：今の気になるリストと `bookmark-backups` のバックアップを照らし合わせて、RJ番号か作品名の完全一致、または確かめた対応になったもの。④ で消したブックマークの作品も入る
- そのうち、手元の候補（フォルダかアーカイブ）の名前に RJ番号が入っていないもの
- アーカイブ（zip / rar / 7z / lzh）も対象。拡張子はそのまま残す
- 1つの候補に2つ以上の RJ番号が当たったとき（全年齢版と R18 版など）は変えず、一覧に「複数の作品に当たる」と出す（設計者の判断：違う RJ番号を付けないことを優先）
- 決め手が作品名の完全一致だけのものも「変えられる」に入れ、最初からチェックを付ける。一覧に決め手（RJ番号が一致／確かめた対応／作品名が一致）を出して見分けられるようにする（設計者の判断：④ で消すときと同じ扱い）
- 同じ作品の候補が手元に複数あっても（フォルダと zip、版違いなど）、変えるのは照らし合わせで選ばれた1つだけ（設計者の判断：名前がぶつからない。残りは次のチェックで RJ番号の一致する方が選ばれるので困らない）
- 照らし合わせで当たった候補をそのまま変える。ただし、当たった候補のすぐ外側のフォルダも同じ作品として当たっている（二重に展開した `作品\作品` など）ときは、外側だけを変える（設計者の判断：内側はゲームの中のフォルダとみなす）

### 新しい名前
- `RJ番号 正式な作品名 v版`（区切りは半角スペース）
- 正式な作品名は DLsite から取る（`Get-DLsiteTitles`）
- 版は今の名前から `Get-FolderVersion` で読めたときだけ付ける。読めなければ `RJ番号 正式な作品名`
- 作品名が取れなかったものは変えず、一覧に「作品名が取れなかった」と出す

### 画面の流れ
1. ③ チェック開始のあとで「フォルダ名をそろえる…」を押す（チェック前なら先にチェックを促す）
2. 作品名を取って、一覧を出す：チェック欄 / 今の名前 / 新しい名前 / 状態（変えられる・作品名が取れなかった・同じ名前がもうある など）
3. 変えられるものは最初からチェック済み。外したいものはチェックを外す
4. 「名前を変える」で実行。終わったら結果（変えた数・変えられなかった数と理由）を出し、候補を集め直してチェックし直す

### 安全のために
- 変える前に、変える予定の一覧を記録ファイルに書き、1件変えるたびに結果を書き足す。途中で止まっても、どこまで変わったかわかる
- 「フォルダ名を戻す…」で記録ファイルを選ぶと、逆向きに戻す。`owned-links.json` はバックアップを書き戻すのではなく、パスの書き換えを逆向きにやり直す（変えたあとに確かめた対応を消さないため。設計者の判断）。元の名前のものがもうある・新しい名前のものが見つからない（手で動かした）ものは飛ばして、最後にまとめて知らせる
- 同じ名前のフォルダ・ファイルがもうあるときは変えない
- ② に登録したゲームフォルダそのものは変えない
- 使用中などで変えられなかったものは飛ばして、最後にまとめて知らせる

### owned-links.json の書き換え
- `same` と `diff` に入っているパスのうち、変えたパスそのもの、またはその下にあるパスを新しいパスに書き換える
- 書き換える前に `owned-links.json` もバックアップする

## 作る人に任せること

- 記録ファイルの置き場所・形（例：このフォルダの `rename-logs\` に JSON。`.gitignore` に追加）
- Windows で使えない文字（`\ / : * ? " < > |`）の置き換え方（全角にするなど）、末尾の点・空白の扱い
- パスが長すぎるときの作品名の切り詰め方
- 別の作品どうしで対象が入れ子になっているとき（サークルのフォルダと作品のフォルダが両方当たったなど）の変える順番（深い方から、など）
- 一覧の画面の細かい見た目。今の画面（`New-ListGroup`、`DataGridView`）に合わせる
- 判定まわりのテスト（今は AS Patch Finder の JS テストだけ）。新しい名前を作る部分・パスの書き換え部分はテストを書きやすい形に分ける

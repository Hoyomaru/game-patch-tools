# ブックマークの書き換えを Edge の拡張機能で行う 設計

2026-11-27

## 目的と理由

所持チェックはブラウザを閉じている間に `Bookmarks` ファイルを直接書き換えている。ユーザーの Edge は同期がオンで、④ で消した 7 件が、次に Edge を起動したあと全部戻っていた（13:27 に消し、13:28 のバックアップでは消えていて、17:15 のバックアップと今のファイルには戻っている。`Bookmarks` に `sync_metadata` があり、Preferences の同期も有効）。

ファイルを外から書き換えると、Edge の同期はその変更を知らない。起動時にファイルと同期の記録が食い違うので、同期サーバーの分と合わせ直し（足し算）、消した分が戻る。同じ理由で「URL をまとめて追加」「ASで見つかった作品をフォルダにまとめる」も、戻ったり重なったりするおそれがある。

ブラウザの正式な仕組み（拡張機能の `chrome.bookmarks`）で書き換えれば、同期にも伝わる。

## ねらい・やらないこと・失敗とみなすこと

ねらい
- 同期がオンのとき、④ 消す・URL をまとめて追加・AS で見つかった作品をフォルダにまとめる、の3つを拡張機能で行い、同期で戻らないようにする
- 同期がオフのときは今のまま（ファイルを直接書き換える）
- 「バックアップから戻す」は、同期がオンなら止めて知らせる

やらないこと
- Chrome ウェブストア・Edge アドオンへの公開（ユーザーが開発者モードで読み込む）
- 拡張機能から所持チェックへ結果を自動で返す仕組み（ネイティブメッセージングなど）
- ほかのブラウザ（Chrome・Floorp）への対応の確認（Chromium 系なら動くはずだが、確かめるのは Edge だけ）

失敗とみなすこと（動いていても）
- 同期がオンなのに、ファイルを直接書き換えてしまう（気づかないうちに戻る）
- ① で選んだフォルダの外のブックマークを消す・動かす
- 拡張機能が、所持チェックから渡されたもの以外のブックマークを書き換える。DLsite 以外のページで動く
- 拡張機能がネットに何かを送る

## 前提・制約

- 拡張機能は Manifest V3。権限は `bookmarks` と、`https://www.dlsite.com/*` の content script だけ
- 所持チェックは今までどおり PowerShell 5.1・追加のインストールなし
- 渡し方は AS Patch Finder と同じく URL の `#` より後ろ（ページを開いてもサーバーに送られない）
- コマンドラインの長さ（約 32,000 文字）を超えないように、多いときは何回かに分ける
- 個人のデータは出力しない（作品名は画面だけ）

## 作り方の候補

| 案 | 中身 | 良いところ | 悪いところ |
|---|---|---|---|
| **1. DLsite のページの `#` で渡し、拡張機能の content script が読む（採用）** | 所持チェックが `https://www.dlsite.com/maniax/#gpt-bookmarks=…` を Edge で開く。content script が読み、service worker が `chrome.bookmarks` で書き換え、結果をページに出す | AS Patch Finder と同じやり方。開き方が確実 | DLsite のページを1回開く |
| 2. 拡張機能のページ（`chrome-extension://…`）を直接開く | 拡張機能の ID を固定し、そのページの `#` で渡す | DLsite を開かない | コマンドラインから拡張機能のページを開けるか確かでない |
| 3. ネイティブメッセージング | 拡張機能と所持チェックが直接やりとりする | 結果を自動で返せる | レジストリへの登録など、入れるのが重い |

ユーザーは「推奨でいい」と答えたので、案1は設計者の判断。

## 決めたこと

### 同期がオンかの見分け
- `Bookmarks` ファイルに `sync_metadata` があって空でなければ「同期がオン」とみなす（設計者の判断：ファイルだけで決まり、確かめやすい）

### 所持チェック側
- 同期がオンのときの ④ 消す・URL をまとめて追加・フォルダにまとめる：
  1. 今までどおり、対象を決めて確認を出す（何件・どのフォルダ）
  2. 念のため `Bookmarks` ファイルのバックアップを取る（今と同じ）
  3. ブラウザを閉じる必要はない
  4. Edge で `https://www.dlsite.com/maniax/#gpt-bookmarks=<渡すもの>` を開く
  5. 「Edge のページに結果が出たら OK を押してください」と待つ。OK のあと、`Bookmarks` ファイルを読み直してチェックし直す
- 拡張機能を入れていないかもしれないので、初回は入れ方（README の節）を案内する。入れたかどうかは設定（`owned-gui-settings.json`）に覚える
- 同期がオンのときの「バックアップから戻す」は、「同期がオンなので戻せません。Edge の『お気に入り』→『削除したお気に入りの復元』を使うか、同期をオフにしてから使ってください」と出して止める
- コマンド版（`check-owned.ps1 -Prune`）も、同期がオンなら消さずに知らせる
- 「たぶん」を消したときに対応を覚える処理は今のまま

### 渡すもの（`#gpt-bookmarks=` の後ろ）
- `encodeURIComponent` した JSON：`{ "v": 1, "op": "delete" | "add" | "move", "folder": "<① のフォルダのパス>", "codes": [...], "items": [{ "code", "title", "url" }], "sub": "<まとめる先の名前>" }`（op ごとに使うものだけ）
- フォルダのパスは所持チェックと同じ形（`ルートの名前 / フォルダ / …`）。拡張機能は、ルートは名前で合わなければ位置（お気に入りバー・その他のお気に入り）で、その下はフォルダ名で探す
- 長すぎるときは、`codes` / `items` を分けて何回かに分けて開く

### 拡張機能側（リポジトリの `edge-extension/`）
- content script：`https://www.dlsite.com/*` で動き、`location.hash` が `#gpt-bookmarks=` で始まるときだけ、中身を service worker に渡し、`history.replaceState` で `#` を消す
- service worker：`chrome.bookmarks.getTree` で ① のフォルダを探し、
  - delete：フォルダの中（サブフォルダ含む）の DLsite の URL で、RJ番号が `codes` にあるものを消す
  - add：フォルダの中にまだない RJ番号だけ、`title`・`url` で足す
  - move：フォルダの中（`sub` の中は除く）から、`codes` のものを `sub`（なければ作る）に移す
- 結果（消した・足した・移した数、見つからなかったフォルダなど）を、そのページの右下に小さく出す
- ネットには何も送らない。`dlsite.com` 以外では動かない

### 読み手のチェックで決めたこと（設計者の判断）
- **リンクを踏んだだけでは書き換えない**：拡張機能は受け取った中身をページの右下に「お気に入り『フォルダ』から N 件を消します」のように出し、**「実行する」ボタンを押したときだけ**書き換える。ほかのサイトに仕込まれたリンクで勝手に消されないようにするため。合言葉は使わない（入れる手段が別に要り、1クリックで足りる）
- **開くブラウザとプロフィール**：`Bookmarks` のパスから Edge のプロフィールのフォルダ名（`Default`・`Profile 2` など）を取り、`msedge.exe --profile-directory=<フォルダ名> <URL>` で開く（既定のブラウザや別のプロフィールに届かないように）。Edge 以外（Chrome など）の `Bookmarks` で同期がオンのときは、書き換えずに「同期がオンの Chrome のブックマークは書き換えられません。ブラウザで消してください」と知らせる（確かめられるのは Edge だけなので）
- **① でフォルダを選んでいないとき**：今のファイル版と同じく、ブックマーク全体を対象にする（`folder` は空）。拡張機能は空ならすべてのルートを見る
- **① に `Bookmarks` が複数あり、同期のオン・オフが混ざるとき**：ファイルごとに今の順で処理し、同期オンの分は拡張機能で（Edge で開いて OK を待つ）、オフの分は今までどおり（ブラウザを閉じてファイルを書き換える）
- **同じパスのフォルダが2つ以上あるとき**：今のファイル版と同じ（消すは当てはまるフォルダ全部、追加とまとめるは最初の1つ）

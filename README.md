# game-patch-tools

ゲームの翻訳パッチ探しと、気になる作品の管理を楽にするための個人用ツール集です。

- **所持チェック**（Windows）：ブラウザのブックマークと手元のゲームフォルダを照らし合わせて、すでに持っている作品かどうかを判定します
- **AS Patch Finder**（Tampermonkey）：フォーラムの検索結果を作品ごとにまとめて、最新版をハイライトします
- 2つを組み合わせると、持っていない作品のスレッド探しと、持っている作品の新しい版探しを AS でまとめて行えます。結果は所持チェックに読み戻せます

## 所持チェック（Windows）

ブラウザのブックマーク（気になる作品のDLsiteのURL）と、手元のゲームフォルダを照らし合わせて、すでに持っている作品かどうかを判定します。

- 判定は作品名の一致・似かたで行います（RJ番号がフォルダ名にあればそれも使用）
- 持っている作品のブックマーク削除、URLのまとめて追加ができます（ブラウザ終了中のみ・毎回バックアップあり）
- ネットにアクセスするのは「URL をまとめて追加」と「フォルダ名をそろえる」で作品名をDLsiteから取るときだけです（送るのはRJ番号だけ）
- 「持っていない作品をASで検索」で、持っていない作品のRJ番号を付けてASの検索ページをブラウザで開きます（検索そのものは下の AS Patch Finder が行います）
- 「持っている作品の更新をASで確認」で、持っている作品をフォルダ名の版といっしょに AS Patch Finder に渡し、新しい版が出ていないか調べられます（1.7.0〜）
- 「たぶん持っている」を自分で確かめた結果を覚えて、次のチェックから使います（1.7.0〜）
- 「フォルダ名をそろえる」で、持っている作品のフォルダ名に RJ番号を入れ、次から確実に判定できるようにします（1.8.0〜）

### 必要なもの

- Windows と PowerShell 5.1 以上（追加のインストールは不要）
- Chrome か Edge（ブックマークを読むため）

### インストール

- **git を使う場合**：`git clone https://github.com/Hoyomaru/game-patch-tools.git`
- **git を使わない場合**：GitHub の「Code」→「Download ZIP」で最新版を、「Tags」から版を選べばその版の ZIP を取れます（リリースを作らなくても、タグごとに ZIP があります）
  - 展開する前に、ZIP を右クリック →「プロパティ」→「許可する」にチェックを入れます。入れないと、起動するたびにセキュリティの警告が出ることがあります

`所持チェック.bat` をダブルクリックすると起動します。黒いウィンドウを出さずに起動したいときは、デスクトップなどに次のショートカットを作ります（パスは置いた場所に合わせる）。

```
C:\Windows\System32\conhost.exe --headless powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File "<置いた場所>\owned-gui.ps1"
```

#### 更新

- **git を使う場合**：`git pull`
- **git を使わない場合**：新しいファイルで上書きします。`owned-gui-settings.json` と `bookmark-backups` は ZIP に入っていないので、そのまま残ります

### 使い方

1. **① 気になるリスト**：「ブラウザのブックマークを追加 ▼」で Chrome / Edge のブックマークを選び、「ブックマークのフォルダ」で DLsite の作品を入れているフォルダを選びます（初回は見つかったブックマークが最初から入っています）。Session Buddy のエクスポートなどは「ファイルを追加…」から
2. **② ゲームフォルダ**：ゲームを置いているフォルダを追加します。つながっていないドライブのフォルダは飛ばして、そのことを知らせます
3. **③ チェック開始**：結果は「持っている」（RJ番号か作品名が完全に一致）・「たぶん持っている」（作品名が似ている）・「持っていない」に分かれます。作品名をダブルクリックで DLsite、手元の候補をダブルクリックでフォルダが開きます
4. **④ ブックマークから消す**：「持っている」は最初からチェックが付いています。「たぶん」は自分で確かめてチェックします。消すときはブラウザを完全に終了しておきます

### 確かめた結果を覚える（1.7.0〜）

表の行を右クリックすると、手元の候補が同じ作品かどうかを覚えさせられます。覚えたことは `owned-links.json` に保存され、次のチェックから使います。

- **この手元の候補で合っている**：次からは「持っている（確かめた）」になります。「持っていない」の行でも、「いちばん近い」候補が出ていれば選べます
- **この手元の候補は別の作品**：次からは、その候補を似ていても選びません
- **この作品について覚えたことを忘れる**：元の判定に戻します
- 「たぶん持っている」にチェックを付けて ④ で消したときも、その候補で合っていると覚えます

### 持っている作品の更新をASで確認（1.7.0〜）

「持っている作品の更新をASで確認」を押すと、持っている作品のRJ番号を AS Patch Finder の「持っている作品」のリストに入れます。AS で「開始」を押すと順番に検索し、手元の版より新しい版があれば「新しい版あり」が付きます。

- 対象は、RJ番号がわかる持っている作品です。① の気になるリストと `bookmark-backups` のバックアップ（④ で消したブックマークが残っている）を手元のフォルダと照らし合わせて「持っている」になった作品と、フォルダ名に RJ番号が入っている作品です
- 手元の版は、フォルダ名の「v1.02」「Ver.23.11.13」などから読みます。読めない作品は、AS のパネルで手で入れられます（手で入れた版は、次に渡したときも上書きしません）

### AS の結果を読み込む（1.7.0〜）

AS Patch Finder の「ファイルに保存（TSV）」で保存した結果を「ASの結果を読み込む…」で読むと、表の「AS」の欄に、見つかったスレッドの数・最新の版・「確認済み」「見送り」の印が出ます。「AS」の欄をダブルクリックすると最新のスレッドが開きます。

「ASで見つかった作品をフォルダにまとめる…」で、AS で見つかった作品（「持っている」と「見送り」の印を付けたものは除く）のブックマークを、① で選んでいるフォルダの中のサブフォルダ（初期値「ASで見つかった」）に移せます。サブフォルダも ① のフォルダの中なので、気になるリストからは外れません。移す前にバックアップを取ります。

### フォルダ名をそろえる（1.8.0〜）

「フォルダ名をそろえる…」を押すと、持っている作品のフォルダ（とアーカイブ）の名前を `RJ番号 正式な作品名 v版` に変えます。フォルダ名に RJ番号が入るので、次のチェックからは作品名がどう書かれていても「RJ番号が一致」で「持っている」になり、更新の確認でも外れなくなります。

- 対象は、③ のチェックで「持っている」になった作品（④ で消したブックマークの作品も含む）のうち、手元の名前に RJ番号が入っていないものです。「たぶん持っている」は、右クリックで確かめると対象になります
- 正式な作品名を DLsite から取ります（送るのは RJ番号だけ）。版は今の名前の「v1.02」などから読めたときだけ付けます
- 変える前に「今の名前 → 新しい名前」の一覧が出ます。チェックしたものだけ変えます。「決め手」が「作品名が一致」のものは、同じ作品か気になるならチェックを外してください
- 次のものは変えません：1つのフォルダに2つ以上の作品が当たったもの、作品名が取れなかったもの、同じ名前のものがもうあるもの、② に登録したゲームフォルダそのもの
- 二重に展開した `作品名\作品名` のようなフォルダは、外側の名前を変えます
- ゲームを起動中のフォルダは変えられません。飛ばして、最後にまとめて知らせます
- 確かめた対応（`owned-links.json`）は新しい名前に書き換えます

変えた記録は `rename-logs` に残ります。「フォルダ名を戻す…」で記録（`rename-日時.json`）を選ぶと、元の名前に戻せます。元の名前のものがもうあるときや、そのあと手で名前を変えたり動かしたりしたものは戻さずに知らせます。

うまく判定されないとき：

- **見る深さ**：ゲームフォルダの何階層下までを作品として見るか。`Games\サークル名\作品名` なら 2。ゲームの中によくあるフォルダ（`www`、`data`、`audio`、`*_Data` など）は見ません
- **判定の厳しさ**：「たぶん持っている」にする似かたの基準（0.3〜0.95、初期値 0.6）。関係ない作品が混ざるときは上げ、見落としが多いときは下げます。「持っていない」でも、似かたが 0.4 以上なら「いちばん近い」候補を表示します

消したり追加したりする前には、毎回 `bookmark-backups` にバックアップを取ります。元に戻すときは、ブラウザを終了してから「バックアップから戻す…」で選びます（戻す前の状態も `Bookmarks-before-restore-…` として残ります）。

設定（`owned-gui-settings.json`）、確かめた対応（`owned-links.json`）、結果レポート、ブックマークのバックアップ、フォルダ名を変えた記録（`rename-logs`）は、このフォルダに保存されます。これらは `.gitignore` でリポジトリの対象から外しています。

## AS Patch Finder（Tampermonkey）

`as-patch-finder.user.js`：フォーラムの検索結果で、タイトルからバージョン・日付・作品コードを抜き出し、作品ごとにまとめて最新版をハイライトします。

### 必要なもの

- Tampermonkey を入れたブラウザ

### インストール

次のURLを開いてインストールします。以降は Tampermonkey が自動で更新します。

https://raw.githubusercontent.com/Hoyomaru/game-patch-tools/main/as-patch-finder.user.js

### 検索結果の整理

- RJ番号で検索すると、そのRJ番号の結果を1つの作品グループにまとめます。タイトルにRJ番号がなく本文だけで当たったスレッドも同じグループに入り、「本文だけで一致」が付きます。これらは最新の候補にはしません（1.5.6〜）
- リクエストスレッド（リクエスト用のフォーラムにあるもの、タイトルが [REQUEST] で始まるもの）は、「リクエストを隠す」で隠せます。初期設定は隠す、です。リクエストは最新の候補にしません（自動検索でも同じ）（1.5.6〜）
- 同じ作品にバージョン番号（v1.02 など）のスレッドと日付版（Ver.23.11.13 など）のスレッドが混ざっていると、そのままでは比べられません。そういう作品だけ、DLsite の作品ページにある「更新情報」を読んで、同じ日付の軸で比べます（1.6.0〜。検索結果の整理・自動検索の両方）
  - 日付版はその日付で比べます。バージョン番号は、更新情報に「Ver1.0.3に更新」のように同じ番号があればその日、なければ投稿日までに出た一番新しい更新の日とみなします。最初の更新より前に投稿されたものは発売時の版として扱います
  - この方法で決まったときは「★ 最新（…DLsite更新情報で判定）」と出ます。更新情報がない作品（古い作品に多い）は今までどおりです
  - 読むのは更新情報だけで、1件500バイトほどです。DLsite への問い合わせは1秒以上あけ、結果は7日間使い回します
  - DLsite に接続するため、1.6.0 に更新するときに Tampermonkey が www.dlsite.com への接続の許可を求めます

### 自動検索（1.3.0〜）

RJ番号のリストを1件ずつASで検索して、見つかったスレッドのURLを集めます。

- 所持チェックの「持っていない作品をASで検索」から開くか、`https://www.anime-sharing.com/search/#apf-auto` を開いてRJ番号を貼り付けます
- 「開始」で検索を始めます。初期設定は8秒に1件です（480件なら約1時間半）。ASのタブは開いたままにしてください（裏に回してもかまいません）
- 途中で止めたり閉じたりしても、次は続きから再開します。30日以内に検索した作品は飛ばします（日数は変えられます）
- エラーになった作品は飛ばして先へ進み、最後にエラーの件数を出します。「開始」でもう一度試せます（1.5.1〜）
- ASに「検索が多すぎる」と言われたら、自動で待ってから続けます
- 作品ごとに最新のスレッドに「★ 最新」が付きます（1.4.0〜）。候補はタイトルにRJ番号があるスレッドで、その中にパッチ/翻訳があればパッチ/翻訳だけで比べます。比べる順は「版の表記（バージョン番号 ＞ 日付版 ＞ なし）→ 番号 → タイトル内の日付 → 投稿日」です
- 検索し直したとき、前回と比べて「新着◯件」「最新が更新（v1.0→v1.1）」の印が付きます（1.5.0〜）。表示を「新着・更新あり」にすると、印の付いた作品だけ見られます。印は「新着・更新の印を消す」を押すまで残ります（1.5.2〜。見る前に検索し直しても、新着の数は足されていきます）
- RJ番号の入ったスレッドが無い作品は、作品名でも検索します（1.5.0〜。スレッドのタイトルだけが対象）。作品名に【】や［サークル名］、「～副題～」があれば外して、本題だけで探します。見つかったものには「作品名で見つかった（要確認）」が付きます
  - 作品名は、所持チェックの「持っていない作品をASで検索」がクリップボードにコピーします。パネルの「RJ番号を貼り付け…」に Ctrl+V で貼り付けて「このリストにする」を押すと読み込まれます（「RJ番号 [タブ] 作品名」の形）
  - RJ番号で見つからなかった作品は、あとから作品名を読み込むと30日を待たずに検索し直します
- 結果は、URLのコピー（最新だけ／すべて。RJ番号・URL・タイトルのタブ区切り）か、TSVファイル（見つけ方・最新・バージョン・パッチ/翻訳・新着/更新の列つき）で保存できます
- リストを入れ替えても前の結果は残ります。溜まってきたら「今のリストにない作品の結果を消す」で、今の検索対象に入っていない作品の結果と作品名を消せます（1.5.3〜）
- 検索結果と作品名はそのブラウザの Tampermonkey の中にだけ保存されます（1.6.0 までは AS のページの保存領域でした。1.7.0 で初めて AS の検索ページを開いたときに移します）。RJ番号のリストはURLの `#` より後ろで渡すので、検索するとき以外はASに送られません（作品名検索では、その作品名の前の方がASに送られます）

### 2つのリスト・確認済みの印・手元の版（1.7.0〜）

- 自動検索のリストは「気になる（持っていない）作品」と「持っている作品（更新の確認）」の2つです。パネルの「リスト」で切り替えます。所持チェックの「持っていない作品をASで検索」は前者に、「持っている作品の更新をASで確認」は後者に入ります。検索結果は作品ごとに共通です
- 見つかった作品に「確認済み」「見送り」の印を付けられます。表示の初期設定は「未確認の作品」で、印の付いていない作品だけが出ます
  - 「確認済み」は、そのあとの再検索で新着・更新が付くと自動で外れます。「見送り」は外れません。もう一度押すと外せます
  - 印はTSVにも出て、所持チェックの「AS」の欄にも出ます
- 持っている作品のリストでは、各作品に手元の版を入れられます（「1.02」「v1.02」「23.11.13」「2023-11-13」など）。ASの最新と比べて「新しい版あり」「手元と同じ版」などが付き、表示を「手元より新しい版あり」にすると、更新がある作品だけ見られます
  - バージョン番号と日付版のように種類が違うときは、DLsite の更新情報で同じ版の日がわかるときだけ比べます
- 前の検索から「〇日以内に検索した作品は飛ばす」の日数がたった作品があると、パネルを開いたときに件数を知らせます。見出しの件数にも「再検索の時期」として出ます

### ASのページと DLsite のページに出る印（1.7.0〜）

- AS のフォーラムのスレッド一覧とスレッドのページで、リストに入っている作品に「持っている」「気になる」と、「確認済み」「見送り」の印が付きます（作品コードがタイトルかURLにあるもの）。スレッドのページでは「確認済み」「見送り」をその場で付けられます
- DLsite の作品ページを開くと、その作品がリストにあるか検索済みなら、右下にASの検索結果（スレッドの数・最新のスレッド・手元の版との比較・印）が出ます。表示に使うのは保存済みの結果だけで、ASにもDLsiteにも問い合わせません
- 1.7.0 に更新すると、Tampermonkey が AS のフォーラム・スレッドのページと DLsite の作品ページでも動くようになります

## 開発メモ

### ファイル

| ファイル | 内容 |
|---|---|
| `所持チェック.bat` | 所持チェックの起動用 |
| `owned-gui.ps1` | 所持チェックの画面 |
| `owned-core.ps1` | 判定・追加・削除の処理本体 |
| `check-owned.ps1` | 所持チェックのコマンド版 |
| `as-patch-finder.user.js` | AS Patch Finder |

### 文字コード

PowerShell 5.1 は BOM のない ps1 を日本語の文字コード（CP932）として読むので、`*.ps1` は **UTF-8（BOM付き）** で保存します。`.editorconfig` と `.gitattributes` で、文字コードと改行（CRLF）をそろえています。

### テスト

AS Patch Finder のバージョンの読み取りや最新の判定を変えたら、次のコマンドで確かめます（Node.js 18 以上。追加のインストールは不要）。

```
node --test tests/
```

### AS Patch Finder の更新の出し方

スクリプトの `@version` を上げてから push すると、Tampermonkey が自動で取り込みます。
